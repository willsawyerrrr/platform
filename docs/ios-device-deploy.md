# iOS device deploy

Keeps an iOS app installed and fresh on the paired iPhone without Xcode, which matters on a free team where installs expire after 7 days.

## Set up an app

From the platform `main` worktree:

```sh
scripts/install-deploy-agent --name <app> --repo <app-main-worktree> [--project-dir ios] [--scheme <scheme>]
```

This installs a launchd agent (`dev.willsawyerrrr.<app>-deploy`) that runs `deploy-main-to-device` (fast-forward `main`, then `deploy-to-device`) hourly and at login, retrying until the phone is reachable. Logs: `~/Library/Logs/<app>-deploy.log`.

The app needs a signing team set locally (e.g. a gitignored `Config/Local.xcconfig`) and exactly one `.xcodeproj` in `--project-dir`, generated by `xcodegen` from `project.yml` if present. The scheme is the project's only scheme unless `--scheme` is given; the built `.app` is read from the build settings.

## Deploy once

```sh
scripts/deploy-to-device --name <app> --repo <worktree> [--project-dir ios] [--scheme <scheme>] [--force]
```

Builds the worktree's current checkout, including uncommitted changes, with `xcodebuild` and installs it with `devicectl`, so it works for WIP builds on any branch. It skips unless the checkout (HEAD plus uncommitted diff) has changed since the last install or the last install is older than `MAX_AGE_DAYS` (default 5); `--force` always installs; `DEVICE` picks a device. State: `~/.local/state/platform/<app>/last-deploy`. Untracked files don't count towards the change check.

A manual deploy of a WIP build is overwritten by the agent's next run if `main` has changed or the install is stale.
